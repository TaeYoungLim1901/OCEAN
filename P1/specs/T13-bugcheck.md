# T13 — 문제별 학습 파이프라인 버그 검사기 `P{n}/src/bugcheck.py`

실행 파이썬: `python`. `n_jobs` ≤ 2. 스크립트 상단 `sys.stdout.reconfigure(encoding="utf-8")`.

**모델을 새로 학습하지 마라.** 저장된 산출물과 기존 코드 경로를 검사한다.
긴 재학습이 필요한 검사는 만들지 말고, 필요하면 「사람이 실행」 명령으로 분리해 보고한다.

## 왜 만드는가 — 실제로 우리를 다치게 한 버그 2건

이 검사기는 가상의 위험이 아니라 **이미 발생한 사고**를 자동화한다. 둘 다 손으로 감사(T7)해서 뒤늦게 찾았다.

**버그 1 — 대칭 purge 로 인한 시간 누수.** `P1/src/features.py` 의 `train_mask_with_purge` 가 대칭 마스크라
`held_out=1` 일 때 학습집합에 fold2·3(미래)이 들어갔다. 그 booster 로 만든 inner OOF 가 미래를 봤고
inner F1 **0.762702** 는 낙관이었다. forward 재구성 후 정직한 값은 **0.697836**. 격자 선택이 오염된 신호 위에서 이뤄졌다.

**버그 2 — 점수 경로 불일치.** `P1/src/exp004.py` 가 test 점수를 booster 4개 **평균**으로 냈는데
튜닝은 fold 당 **단일 모델** 점수 위에서 했다. 평균이 확률을 중앙으로 압축했고
(test p50 **0.003126** vs 단일 **0.000004**) threshold 0.54 에서 test 양성률이 **0.032039** 로
train **0.041362** 보다 낮아졌다. exp005 가 4경로를 단일 모델로 통일해 해소했다.

### 기준선 숫자 (확정. 재측정 금지)

P1 현재: forward inner F1 **0.697836**, 봉인 outer fold3 **0.815757**, public LB **0.717435**.
exp005 제출 sha256 `5E5B8840C3A6FC5E6C8A8DFD461E419E9795548492C566E27758EE5BD0185F5A`,
행 169011, 양성 5880 (**3.4791%**), train 양성률 **0.041362**.

운영진이 **제출 모델이 업로드한 예측 답안을 재현하는지 검증**하며 실패하면 최종 성적으로 인정되지 않는다.
이 재현 검증이 C5 의 존재 이유다.

## 배경 — 재조사 금지 사실 (확정. 다시 측정하거나 의심하지 마라)

- P1 기각축: 유형 multiclass blend, stream 별 양성률 앵커링, 랜덤 행 CV, adversarial drift 를 보정기로 사용.
- exp005 선택(threshold 0.62 / hole 48 / weight 0)은 확장 격자에서 내부 최적임이 확인됐다.
- 봉인 fold3 는 이미 3회 판독됐다. **검사기가 봉인 fold3 를 채점하게 만들지 마라.**
- 사용 가능 라이브러리는 numpy·pandas·scikit-learn·lightgbm 뿐이다. xgboost·catboost·torch 는 없다.
- P2 는 리더보드 점수 대기로 막혀 있다. P2 파이프라인을 바꾸려 하지 마라. 읽고 검사만 한다.

## 산출물

`P1/src/bugcheck.py`, `P2/src/bugcheck.py`, `P3/src/bugcheck.py` — **독립 파일 3개.**
**공유 모듈을 만들지 마라.** 세 문제는 분할·지표·산출물이 전부 다르다
(P1 = 87h 한쪽 purge forward fold, P2 = 2024-09~10 홀드아웃, P3 = 78h 시닝).
공통 프레임을 만들면 구현 1개짜리 추상화가 된다. 같은 것은 **검사 항목의 의미**뿐이다.

인터페이스는 각 문제의 기존 `check.py` 와 같은 모양으로 맞춘다
(`verdict(fails)` 패턴, `판정: OK` / `판정: STOP`, 실패 시 exit ≠ 0):

```
python P{n}/src/bugcheck.py all
python P{n}/src/bugcheck.py C3
python P{n}/src/bugcheck.py --selftest
```

## 검사 항목 — 문제마다 그 문제의 실제 파이프라인에 배선한다

| ID | 검사 | 무엇을 실제로 확인하나 |
|---|---|---|
| C1 | **시간 누수** | 각 fold 에 대해 학습 마스크를 **정의로부터 다시 계산**하고, 학습 행의 시간이 평가 구간 시작 − purge 이후인 행 수가 **정확히 0** 인지. 저장된 마스크를 믿지 말고 재계산한다. 버그 1 이 이것이다 |
| C2 | **통계 누수** | climatology·σ·정규화·인코딩이 **학습 행에서만** 적합됐는지. 학습 인덱스만으로 다시 적합해 저장값과 비교한다. 불일치하면 누수 |
| C3 | **점수 경로 일치** | OOF 를 만든 추정기 구성과 test 를 만든 추정기 구성이 같은지: 트리 수, **평균/앙상블 적용 여부**, feature 목록, 후처리 순서. 그리고 oof 와 test 예측의 분포 분위수(p50·p90·p99·max)를 비교해 압축 흔적을 잡는다. 버그 2 가 이것이다 |
| C4 | **예측 배열 정합** | 길이 = 인덱스 길이, NaN·inf 없음, 확률은 [0,1], 키 정렬이 인덱스와 일치, 양성률이 선언된 밴드 안. **추가: `P1/preds` 폴더의 배열이 이진화(고유값 2개, uint8)되어 저장돼 있으면 FAIL.** 2026-08-25 에 `oof/test_exp002~005.npy` 가 전부 uint8 0/1 로 저장돼 있어 임계 재탐색·앙상블 재조합이 원천 불가였다. 원시 확률은 float 로 남겨야 한다 |
| C5 | **재현성** | 저장된 산출물만으로 추론을 다시 돌려 제출 CSV 의 **sha256 이 기록값과 일치**하는지. `SEED = 42` 가 코드에 실제로 있는지. 산출물이 없으면 **건너뛰지 말고 FAIL** |
| C7 | **학습 건전성** | 모델이 퇴화하지 않았는지: 트리 수 = 기대값, 중요도가 0 이 아닌 feature 수 > 0, 예측 std > 0, 학습집합 점수 > 자명한 기준선 |
| C8 | **원본 데이터 무결성** | 원본 데이터 파일의 sha256 이 기록값과 같은지 (기록이 없으면 최초 1회 기록하고 그 사실을 출력). dtype·결측 센티널 |
| C9 | **학습/추론 분리** | 추론 경로가 label 을 읽지 않고 아무것도 재적합하지 않는지. `train`/`inference` 모듈 분리가 유지되는지 (`AGENTS.md` §7 은 심사 산출물이라 분리를 요구한다) |

### C6 — fail-closed 자체검사 (가장 중요)

`--selftest` 는 **각 검사를 일부러 깨뜨리고 검사가 실제로 잡는지 확인한다.**
합성 픽스처를 메모리에서 만들어(원본 데이터 수정 금지) 최소 다음을 포함한다:

- C1: 대칭 purge 마스크(버그 1 재현) → C1 이 FAIL 해야 한다
- C2: 전체 데이터로 적합한 climatology → C2 가 FAIL 해야 한다
- C3: 예측을 4개 평균으로 압축(버그 2 재현) → C3 이 FAIL 해야 한다
- C4: 길이 1 짧은 배열, NaN 1개 → C4 가 FAIL 해야 한다
- C5: 산출물 파일 부재 → C5 가 **SKIP 이 아니라 FAIL**
- C7: 상수 예측 모델 → C7 이 FAIL 해야 한다

**기준이 없을 때 통과시키는 검사, 자기 자신과 비교하는 검사는 검사가 아니다.**
`--selftest` 가 하나라도 「깨뜨렸는데 통과」를 만들면 exit ≠ 0.

## 제약

- **새 의존성 금지. `pip install` 이 필요하면 실행하지 말고 멈추고 보고한다.**
- 원본 데이터 폴더(`P1/P1_data` 등)는 **읽기 전용**. 수정·재배포 금지
- **기존 파일을 수정하지 마라.** 새 파일 3개만 만든다. 기존 `check.py`·`train.py`·`inference.py`·
  `features.py`·`submission_tools.py` 의 인터페이스를 바꾸지 마라
- 검사기가 통과시키려고 기준을 느슨하게 잡지 마라. 판단이 애매하면 **FAIL 쪽으로 기울이고** 사유를 출력한다
- 각 파일 250줄을 넘기지 마라. 새 클래스 계층·설정파일·로깅 프레임워크 금지. `print` 로 충분
- 검사에 필요한 기대값(트리 수·양성률 밴드·sha256)은 **파일 상단 상수 블록 한 곳**에 모으고 출처 주석 1줄을 붙인다
- 동시에 다른 프로세스가 `P1/src/features.py`·`P1/src/exp007.py`·`P1/specs/`·루트 `RULES.md` 를 쓰고 있다.
  **그 파일들을 수정하지 마라.** 읽기는 해도 된다

## 수락 기준

세 문제 각각에 대해 다음을 **실행하고 숫자를 보고**한다:

```
python P1/src/bugcheck.py --selftest
python P1/src/bugcheck.py all
python P2/src/bugcheck.py --selftest
python P2/src/bugcheck.py all
python P3/src/bugcheck.py --selftest
python P3/src/bugcheck.py all
```

`--selftest` 는 전부 exit 0 이어야 한다 (= 깨뜨린 것을 전부 잡았다).
`all` 은 exit 0 일 필요가 **없다** — 진짜 결함을 찾았으면 FAIL 이 맞다.
FAIL 이 나오면 **고치지 말고** 그 항목과 숫자를 보고한다.
