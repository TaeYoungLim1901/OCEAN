## 1. 무엇을 만드는가

3문제(P1·P2·P3)를 **각각 독립 세션**에서 푼다. 세션이 공유하는 것은 규약과 도구,
공유하지 않는 것은 데이터·실험·그래프다.

```
OCEAN/
  CLAUDE.md              @AGENTS.md import + 토큰 규칙
  AGENTS.md              공통 실행 계약 (문제 무관)
  PLAYBOOK.md            절차 (기존)
  docs/GRAPH.md          온톨로지 읽는 법
  scripts/g.py           그래프 질의 CLI (--p P3)
  scripts/preflight.py   사양 게이트(공통) + 제출 게이트(P3 스키마)
  scripts/cx.sh          codex 위임 래퍼
  .claude/skills/{cx,score,graph}/
  P3/
    AGENTS.md            P3 사실·제약 (트리 소유 계약)
    graph.json           P3 온톨로지
    P3_data/             읽기 전용 원본
    src/{metric,cases,features,check}.py
    preds/ subs/ specs/ experiments/ cache/
```

**소유 경계**: 세션은 자기 `P{n}/` 만 쓴다. 루트 파일 수정은 사용자 승인.
BARAM 에서 동시 실행이 `cache/models/` 를 오염시킨 사고가 2회 있었다.

## 2. 온톨로지 — 왜 그래프인가

BARAM 실패 중 재발률 1위는 **이미 닫힌 축을 다시 연 것(5회)**이었다. 원인은 지식이
산문 문서에 흩어져 있어 "이미 측정했는가"를 사람 기억으로 판정한 것이다.

`graph.json` 은 그 판정을 명령어로 바꾼다.

| 타입 | 뜻 | 집합 연산 |
|---|---|---|
| `rule` | 대회 규정에서 유도된 제약 | 위반 검사 = `axis ∩ forbids ≠ ∅` |
| `fact` | 실측으로 확정, 재조사 금지 | 새 실험이 재측정하면 낭비 |
| `physics` | 도메인 지식(파랑 물리) | 가설의 근거 노드 |
| `axis` | 실험 축. `open`/`running`/`closed` | 새 실험 = `open` 집합의 원소여야 함 |
| `asset` | 보존된 예측 파일 | 앙상블 풀 = `asset` 전체 |
| `gate` | 실행 전 통과해야 할 체크 | — |

엣지: `forbids · requires · derives_from · closes · measures`.

**토큰 절약이 부수효과가 아니라 목적이다.** 노드 1개 질의 = 3줄 출력. 문서 통독 대신
`g.py show p.decay` 를 쓴다. BARAM 은 `experiments/log.md` 가 139k 토큰까지 자랐다.

## 3. 사전 게이트 — 토큰 태우기 전

| 게이트 | 언제 | 잡는 것 |
|---|---|---|
| `preflight.py spec` | codex 호출 전 | python 경로, 출력 디렉터리, 절대 수락기준, 가설 1개, 대조군, 결론문장 금지 |
| `preflight.py sub` | P3 제출 전 | P3 열 순서·키 집합·행수·범위·NaN, persistence 대비 Δ |
| `check.py data` | 최초 1회, 전처리 변경 시 | 격자·중복·역행·정점 커버리지 |
| `check.py cases` | 사례 생성 변경 시 | 학습/test 컨텍스트 형태와 사례선정 분포 |
| `check.py cv <fold.csv>` | 폴드 생성 후 | 정점별 폴드 경계의 t0 간격이 78h 미만인지 |
| `check.py pipeline` | 하네스 변경 시 | **persistence 재현 = `baseline_persistence.csv` 완전일치** |

마지막 것이 P3 의 행운이다. 정답이 없어도 생산 경로를 바이트 단위로 검증할 수 있다.
BARAM 은 집계 기본값 불일치로 0.0127 을 놓치고 2회 오판했다.

`check.py cv`는 현재 fold CSV의 시간 간격만 검사한다. 달력 피처·t0 이후 입력 혼입은 자동으로
찾지 못하므로 사양과 코드 검토에서 별도로 확인한다.

## 4. P3 실측 사실 (설계를 바꾼 것)

| 사실 | 영향 |
|---|---|
| I-ORS·S-ORS `train_atmos` 는 **2025-01-01 부터만** (26,064행 vs G-ORS 78,768행) | 2024년 I/S 는 파랑 단독. 기상 피처 모델의 학습량이 정점마다 다르다 |
| test 에 절대시각 열 없음 | 달력 피처 전면 금지. 계절은 `airt`·`caph` 역추정만 |
| 파랑 20분·기상 10분 격자 완전 (갭 0) | 리샘플 불필요. 결측은 값 결측뿐 (hs 8.7%) |
| 사례 조건 t0 `hs≥1.5`, 6리드 유효 | 학습 표본을 같은 조건으로 뽑아야 한다. 무조건 표본은 분포가 다르다 |
| hs≥1.5 비율 G 26% / I 19% / S 18% | 정점별 사례 밀도가 다르다 |
| 지표 = 통합 RMSE | 최적 예측은 **조건부 평균**. 분위수·MAE 목적함수는 목표가 아니다 |
| 리드별 persistence RMSE 0.546→0.946 | +18/+24h가 지속성 기준 SSE의 약 47.5%를 차지한다 |

## 5. 검증 설계 — 판정기가 아니다

train `2024-01-01~2025-06-30` / test `2025-07-04~2026-06-30`. 겹치지 않고, test 는
연 1주기를 다 돈다. 학습에는 7~12월이 **1번뿐**이다.

⇒ 어떤 로컬 홀드아웃도 "미래 연도" 간극을 복제하지 못한다. **이 CV 는 탐색기다.**
판정은 리더보드(8/20 개시, 하루 1회)로 하고, 제출 예산을 사전 배분한다.

폴드는 t0 기준 시간분할 + case 그룹 분리. 컨텍스트 48h·타깃 24h 가 폴드 경계를 넘지
않도록 78h 완충을 둔다(대회 사례 간격과 동일).

## 6. 모델 방향 (Phase 1, 확정 아님)

기저를 여러 계열 세우고 **모든 예측을 보존**한다(`preds/oof_{model}_{ver}.npy`, 진 실험 포함).
BARAM 상승분 100% 가 기존 예측의 재조합에서 나왔고 그것을 9일차에 했다.

1. 감쇠 persistence — 학습 0회, 파라미터 2개. 진짜 기준선
2. LightGBM 리드별 직접예측 (컨텍스트 요약 피처)
3. 정점 pooled + station 지시자 (I/S 2024 기상 결측 우회)

`xgboost`·`catboost`·`torch` 는 미설치. 필요해지면 사용자에게 요청한다.
