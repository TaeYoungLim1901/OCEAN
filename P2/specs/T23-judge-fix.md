# T23 — judge_sepoct 가 E006 실험만 판정하는 버그를 고치고 A0·A1 을 채점한다

## 버그 (재조사 금지, 원인 확정됨)

`P2/src/judge_sepoct.py`:

```python
def _logical_name(stem):
    return re.sub(r"_S[1-4]_E006$", "", stem)
```

실험 번호 `E006` 이 하드코딩돼 있다. `_candidate_pool` 은 4개 창 전부에 배열이 있는 후보만
채점하고 나머지는 skip 하므로, **E006 이 아닌 실험은 전부 skip 된다.**

2026-08-26 실측: 풀 30개 중 28개 skip. 방금 학습한 `A0`·`A1`(E020) 도 8개 파일 전부 skip 됐다.
`baseB2`(E019)가 통과한 것은 T19 가 `oof_baseB2_S1_E006.npy` 같은 파일을 **추가로** 써서
우연히 패턴에 맞았기 때문이다.

## 할 일

### 1. `_logical_name` 수정

실험 번호를 가리지 않도록 고친다. `_S[1-4]_E<숫자>$` 와 `_2024_sepoct_E<숫자>$` 를 모두 벗긴다.
`preferred` 변수의 `_E006` 하드코딩도 같은 방식으로 고친다 (동명 후보가 여러 실험에 있으면
**실험 번호가 큰 쪽**을 쓴다).

### 2. T19 가 남긴 오해 소지 파일 정리

아래 4개는 E019 산출물인데 파일명이 E006 이라 실험 이력을 오염시킨다. 1번 수정 후에는
불필요하므로 삭제한다. 삭제 전에 같은 내용의 `_E019` 파일이 존재하는지 바이트 비교로 확인하고,
다르면 삭제하지 말고 **멈추고 보고해라.**

```
P2/preds/oof_baseB2_S1_E006.npy
P2/preds/oof_baseB2_S3_E006.npy
P2/preds/oof_baseB2_S4_E006.npy
P2/preds/test_baseB2.npy
```

`P2/preds/test_baseB2.npy` 는 `test_baseB2_E019.npy` 와 비교한다.

### 3. 판정기가 제출 CSV 를 쓰는 부작용을 막는다

현재 `judge_sepoct.py` 실행이 `P2/subs/E013_stack_sepoct.csv` 를 만든다.
판정기는 읽기 전용이어야 한다. `--write-artifacts` 플래그를 줄 때만 쓰도록 바꾼다.
기본값은 쓰지 않는다.

### 4. 재실행하고 표를 보고한다

```

```

표1(후보 × 창)에 최소한 `A0` · `A1` · `maskaug` · `baseB2` · `base_nom` 이 나와야 한다.
