# T17 — bugcheck.py `train`: 학습 파이프라인 논리 감사

## 목적

「모델이 논리적으로 옳은 구조인가, 옳은 데이터로 옳게 학습하는가」를 기계로 검사한다.
T16 은 제출 CSV 사이의 관계만 본다. 이 사양은 **학습 이전 단계**를 본다.
검사 항목은 전부 이 프로젝트에서 **실제로 터졌던** 실패모드다. 가상의 위험이 아니다.

## 배경 — 이미 검증된 사실이다. 재조사하지 마라

- `P3/src/bugcheck.py` 는 T16 에서 이미 생성됐다. **파일을 다시 만들지 말고 서브커맨드만 추가**한다.
  기존 `all`·`wcurve` 의 동작·출력 형식을 바꾸지 마라
- 하드 제약(`r.context_only`): 추론은 해당 `case_id` 의 289행 컨텍스트만 쓴다.
  다른 test case 통계로 정규화하는 transductive 방식 금지. 절대시각 단서 없음 → 달력 피처 금지
- 피처 함수는 `(289, 10) float32` 배열 하나만 받는다. 열 순서는 `cases.COLS` 고정
  (`hs tp hmax wvdir wspd gust wdir airt relh caph`)
- 과거 사고 1 — **fold0 누수**: `train.py` 의 대칭 `abs(hours)` 마스크가 미래 데이터를 학습에 넣었다.
  T10 에서 strict-forward 로 고쳤고 fold0 은 학습행 0 이 되어 건너뛴다 (OOF NaN 56건).
  수정 후 fold4 학습행은 **6828** 이다 (수정 전 6830)
- 과거 사고 2 — **T6 폴백**: 216건 중 79건이 `wspd` 전결측 폴백 경로로 갔는데 아무도 몰랐다
- 분리 근거: `forward_train_mask` (`train_dense.py:175`, `train_t2.py:47-53`) 가 정점별로
  `t0 < 검증시작 − 78h` 를 강제한다. 78h > 컨텍스트 48h + 최대리드 24h = 72h, 여유 6h
- `check.py cv` 는 **씨닝 평가분할 전용**이다. 조밀 인덱스에 걸면 FAIL 이 뜨는데 누수가 아니다
  (`f.dense_cv_gate_na`). `train` 서브커맨드는 이 착각을 반복하지 마라
- 새 의존성 없다. **`pip install` 이 필요하다고 판단되면 실행하지 말고 멈추고 보고하라**

## 산출물

`P3/src/bugcheck.py` 에 서브커맨드 `train` 추가. 한 줄 = 한 검사, `PASS/FAIL/SKIP` + 숫자.
하나라도 FAIL 이면 exit 1. **학습을 새로 돌리지 마라** — 저장된 산출물·설정·코드만 본다.
무거운 재계산이 필요한 검사는 최대 200 컨텍스트 표본으로 제한한다.

## 검사 항목

### A. 시간 분리 (누수)
- **A1 strict-forward**: 각 fold 에 대해 `forward_train_mask` 를 재계산하고
  `max(train t0) < val_start − 78h` 를 정점별로 확인. fold별 학습행 수를 찍고 fold4 를 6828 과 대조
- **A2 리드 도달**: 학습행의 `t0 + max_lead(24h)` 가 검증창에 들어가는 행이 0 인가
- **A3 컨텍스트 도달**: 학습행의 `t0 − 48h` 부터 `t0` 까지 구간이 검증창과 겹치는 행이 0 인가
- **A4 대칭마스크 잔존**: `P3/src/` 전체에서 `abs(` 가 시간차 마스크에 쓰인 곳이 남아 있는가
  (grep 수준으로 충분. 발견 시 파일:행 보고, 판정은 WARN)

### B. 학습·추론 경로 동일성
- **B1 피처 동일성**: 무작위 100 컨텍스트에 대해 학습 경로 피처와 `inference*.py` 경로 피처의
  `max|Δ|`. 0 이 아니면 FAIL
- **B2 시그니처**: 피처 함수가 `(289,10)` 배열 **하나만** 받는가 (`inspect.signature`).
  추가 인자가 있으면 그것이 무엇인지 찍는다
- **B3 열 순서**: `cases.COLS` 가 고정 10열 순서와 일치하는가

### C. context_only 하드 제약
- **C1 사례 독립성**: 200 사례 중 50개를 뽑아, **다른 사례들의 컨텍스트를 무작위 셔플·스케일**한 뒤
  대상 사례 예측이 비트 단위로 불변인가. 변하면 transductive 누수 = FAIL
- **C2 절대시각**: 피처 계산에 인덱스·타임스탬프·행번호가 값으로 들어가는가.
  컨텍스트 행에 상수 오프셋을 준 사본으로 예측이 불변인지 확인
- **C3 t0 이후**: 컨텍스트 마지막 행 이후 데이터에 접근하는 슬라이스가 있는가 (정적 검사)

### D. 데이터 위생
- **D1 폴백률**: 피처별로 결측·폴백 경로를 탄 컨텍스트 비율 상위 5개를 찍는다.
  `wspd` 전결측 비율을 반드시 포함. 임계 없음, 보고만 (WARN)
- **D2 OOF NaN**: `P3/preds/oof_*.npy` 각각의 NaN 개수와 형태. fold0 유래 56건과 대조
- **D3 정렬**: OOF 배열 길이가 대응 평가 인덱스 행수와 일치하는가
- **D4 범위**: 학습 타깃 `hs` 의 min/max/NaN 수. 0 미만·30 초과가 있는가

### E. 재현성
- **E1 SEED**: `P3/src/` 에서 난수 사용처 중 seed 가 고정되지 않은 곳 (grep, WARN)
- **E2 피처 결정성**: 동일 컨텍스트 100개를 2회 계산해 비트 동일인가

## 금지

- 학습 재실행 금지. `P3/preds/`·`P3/subs/`·`P3/cache/` 쓰기 금지. 원본 데이터 쓰기 금지
- 기존 게이트 스크립트 재구현 금지. 기존 `all`·`wcurve` 출력 변경 금지
- 추상화 금지. 클래스 계층·config 파일·로깅 프레임워크 만들지 마라
- 검사가 코드 수정을 필요로 한다고 판단되면 **고치지 말고 FAIL 로 보고**하라. 판정은 Opus 가 한다

## 수락 기준 (직접 실행하고 숫자를 보고하라)

```
python P3/src/bugcheck.py train
python P3/src/bugcheck.py all
```

**결론 문장 금지, 숫자와 표만.** 검사 ID별 PASS/FAIL/SKIP·측정값, 두 명령의 exit code.
SKIP 은 이유를 6단어 이내로. `all` 은 T16 대비 출력이 바뀌지 않았음을 확인용으로만 찍는다.
